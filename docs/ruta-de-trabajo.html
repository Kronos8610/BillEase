# Fotografía de partida — se ejecuta UNA vez, en la fase 0
python tools\baseline.py --escribir     # → tests/fixtures/baseline.json
python tools\seed_demo.py --salida tests\fixtures\baseline.db

El JSON se versiona (son cifras, no datos personales); la base de referencia no: se regenera con seed_demo.py, que produce filas idénticas a las de la original. Así ningún .db vuelve al repositorio. El sha256 del fichero de partida queda anotado dentro del JSON como procedencia.

Cómo se trabaja

Cinco reglas que no se saltan

Una fase, una rama, un pull request. Nada de mezclar fases: si la fase 2 sale mal, se revierte sin arrastrar la 1.

La puerta anterior en verde antes de empezar la siguiente. Todas las comprobaciones de la puerta marcadas, no «casi todas».

Cada fase deja la aplicación ejecutable. python main_start.py abre, lista facturas y genera un PDF al terminar cualquier fase — nunca se queda a medias entre dos.

Primero el test, después el arreglo. Para cada defecto: se escribe la prueba que falla, se arregla, la prueba pasa. Así queda cerrado para siempre.

La base de datos nunca se toca sin copia. Toda migración se prueba antes sobre tests/fixtures/baseline.db y se ejecuta con --dry-run primero.
